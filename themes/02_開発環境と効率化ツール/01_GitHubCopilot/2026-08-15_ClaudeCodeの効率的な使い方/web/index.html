Claude Code セッションを最大活用する

AIを使いこなすための「賢い」使いかたを、効率とコストの両面から解説します。

1. トークンコストとキャッシュの仕組み

AIへの命令には「入力（Prefill）」と「出力（Decode）」の2つの段階があります。特にDecode（生成）のコストは入力の約5倍かかるため、無駄な出力を減らすことが重要です。

ここで鍵となるのがPrompt Cachingです。一度読み込んだ共通の指示や履歴を「キャッシュ」として再利用することで、次からのリクエストコストを大幅に削減できます。

2. 状況に応じた履歴管理（3つのコマンド）

履歴をどう扱うかで、AIの賢さとコストのバランスが決まります。以下の3つを使い分けましょう。

  • /clear: 別のタスクに移る時。履歴を完全にリセットし、ノイズを排除します。
  • /rewind: 直近の操作だけをやり直したい時。前方のキャッシュを維持したまま、失敗した部分だけを取り消します。
  • /compact: 同じタスクで履歴が長くなりすぎた時。内容を要約して、AIがスムーズに動けるように整理します。

3. コンテキストを「賢く」管理する

AIに「探させる」のは、コストの無駄です。

  • @メンションを活用しましょう。ファイルパスを直接打つのではなく、`@ファイル名` とすることで、AIは最初からその内容を把握でき、無駄なReadコールを防げます。
  • CLAUDE.md を最適化しましょう。汎用的な指示はここへ、ワークフロー固有の指示は「スキル」へ。必要な情報だけを適切な場所に置くのがコツです。

4. 複雑なタスクを賢く分離する

すべてをメインの会話でやらせないことも重要です。

  • サブエージェントの活用: ログ解析や大量のファイル探索など、情報量が多く単発の作業はサブエージェントに任せましょう。結果だけをメインコンテキストに戻すことで、全体の処理を高速化できます。
  • 出力の抑制: テスト実行など、大量のテキストが出るコマンドには `quiet` や `tail` を組み合わせて、必要な情報だけがAIに伝わるように調整します。

5. まとめ：効率を最大化する3つの鉄則

  1. キャッシュを意識する（モデル変更はセッションの最初かクリア直後に）
  2. 履歴を整理する（/clear, /rewind, /compact の使い分け）
  3. 情報を絞り込む（@メンションとサブエージェントの活用）

用語解説

Prefill
モデルが推論を開始する前に、プロンプトや履歴を処理する段階。
Decode
AIが1トークンずつ生成する段階。計算負荷が高く、コストも高い。
Prompt Caching
共通の入力内容を再利用し、再計算を省く技術。
Subagent
メインの会話とは別に独立したコンテキストで動く補助AI。
