OVERVIEW

Codexオートメーションとは？

人が毎回頼んでいた確認作業を、Codexが決まった間隔で見に行く仕組みです。

一言で

「頼む」から「定期的に見てもらう」へ。

予定する

日次・週次・カスタムcronなど、決まったタイミングで実行します。

確認する

PR、ログ、資料、TODO、リンク切れなどをCodexが点検します。

報告する

発見があればTriageやスレッドに報告し、何もなければ静かに終了します。

AUTOMATION TYPES

Thread automationとStandalone automation

Thread automation

同じ会話に戻る定期実行。デプロイ見守り、継続レビュー、長い調査に向きます。

Standalone automation

毎回独立した点検。週次PR確認、複数プロジェクトの定期監査に向きます。

理解度チェック

進行中の1件を追うならThread、毎回独立した点検ならStandaloneです。

CHOICE GUIDE

どの自動化を選ぶ？

同じ会話の文脈を残すか、独立実行にするか、CIで動かすかで選びます。

SAFETY

無人実行の安全設計

要素役割最初のおすすめ
Worktree自動化の差分を手元作業から分離修正案を作る自動化で使う
read-only読むだけ。変更はしない最初の定期点検
workspace-writeワークスペース内の編集を許可レビュー可能なパッチ作成
Rules許可する操作を絞る繰り返し実行前に整える
QUALITY

AGENTS.mdとSkillsで品質を固定する

AGENTS.md

リポジトリの作業ルール。テスト、レビュー観点、禁止事項を固定します。

Skills

再利用する手順書。月次点検やPR見守りのレシピに向いています。

EXTEND

Hooksとcodex exec / GitHub Action

Hooks

Codexの動作前後に、独自チェックやログ処理を差し込みます。

codex exec

スクリプトからCodexを非対話で実行します。

GitHub Action

PRレビューやCI失敗調査にCodexを組み込みます。

ACTION

明日からの導入3ステップ

1. 手作業で試す

普通のスレッドで作業範囲、報告条件、停止条件を確認します。

2. read-onlyで点検

最初は読むだけの週次点検から始めます。

3. Worktreeで修正案

必要になったら、分離した場所でパッチを作ります。
