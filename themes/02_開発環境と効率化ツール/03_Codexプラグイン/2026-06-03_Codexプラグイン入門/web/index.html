INTRO

プラグインは「AI用の部品箱」

Codexに、得意技・外部窓口・追加道具をまとめて渡す仕組みです。

一言で

プラグインは、Codexが仕事を進めるための部品を整理して配るパッケージです。

1

手順を覚えさせる

毎回説明している作業手順をSkillとして取り出せる形にします。

2

外部につなぐ

GmailやDriveなどの外部サービスと連携する入口になります。

3

専用ツールを追加する

MCP serverを通じて、独自ツールや共有情報へ接続できます。

ANATOMY

中身は3種類: Skill・App・MCP

Skillは手順書、Appは外部サービスの窓口、MCPは専用ツールの接続口です。

S

Skill

特定作業の手順書。Codexが必要に応じて読み、正しい進め方を守ります。

A

App

外部サービスとの接続。認証やサービス側の規約確認が重要です。

M

MCP

外部ツールや共有情報をCodexに渡すための接続規格です。

SkillとPluginの違いは？▼
Skillは1つの作業手順書。PluginはSkill、App、MCPなどをまとめて配るパッケージです。
INSTALL

インストール後は「新しいスレッド」で使う

1

使う流れ

  • Pluginsを開いて探す
  • Add to Codexで追加
  • 必要なら外部サービスを認証
  • 新しいスレッドで依頼する
2

頼み方

  • 「今日の未読メールを要約して」
  • 「@gmail を使って下書きを作って」
  • 目的かプラグイン名を明示する
BUILD

自作は「plugin.json + SKILL.md」から始める

1

plugin.json

プラグインの名札です。名前、バージョン、Skillの場所などを書きます。

2

SKILL.md

作業手順書そのものです。いつ使うか、何を先に読むか、どんな順番で進めるかを書きます。

PERMISSION

共有と権限は「3層」で見る

1

Codex側の承認

プラグイン導入後も承認設定やサンドボックスの考え方は続きます。

2

外部アプリ側の認証

接続先サービスのログイン、規約、プライバシーポリシーも関係します。

3

組織ポリシー

ワークスペースの管理者設定で、共有や利用が制限されることがあります。

WRAP UP

小さく作って、必要な人に配る

1

まずSkillで型を作る

毎回説明している作業手順を1つ文章化します。

2

必要ならPluginに包む

チーム配布や外部連携が必要になったらプラグイン化します。

3

権限と運用を決める

誰が使うか、何を読めるか、誰がメンテナンスするかを決めます。

参考: OpenAI Codex Manual / Plugins、Build plugins（2026年6月3日確認）
