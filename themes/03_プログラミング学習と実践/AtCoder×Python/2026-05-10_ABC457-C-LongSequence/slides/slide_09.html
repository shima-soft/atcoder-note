C問題

定番の二分探索パターンで制約を確認する癖をつけよう

⏱️ 計算量分析
入力処理: O(Σ L_i) = O(2×10⁵)
累積和構築: O(N) = O(2×10⁵)
二分探索: O(log N) = O(18)
✅ 全体計算量
O(N log N + Σ L_i)
最悪: 2×10⁵ × 18 + 2×10⁵ ≈ 360万 操作
Python でも 0.1〜0.5秒で十分終了
🎯 このパターンの応用先
  • • 範囲クエリ全般（区間検索）
  • • 累積和 + 二分探索は AtCoder 定番
  • • モジュロを使った「繰り返し内の位置」計算
📊 制約との照合
N ≤ 2×10⁵
Σ L_i ≤ 2×10⁵
C_i ≤ 10⁹
K ≤ Σ(L_i × C_i)
💡 このパターンが機能する理由
元データは小さい: Σ L_i ≤ 2×10⁵
繰り返し数が大きい: C_i ≤ 10⁹
→ B 全体を構築できない
→ でも累積和なら O(N) で OK
🧠 学べる思考
  • • 「素朴で通らない」→ 制約から理由を推測
  • • 「事前計算の活用」の大切さ
  • • 「シンプルな実装 = 間違いが少ない」
