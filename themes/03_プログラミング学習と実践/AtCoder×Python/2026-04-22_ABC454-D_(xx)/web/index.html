問題を読み解く

文字列Aを文字列Bに変換できるか？

(・x・) の3種類だけからなる文字列。2つの操作を何度でも使って変換できるか判定します。

使える操作（2種類）

1
(xx) → xx
隣り合う2つのxを囲む括弧を外す
2
xx → (xx)
隣り合う2つのxの周りに括弧を付ける

どちらの操作も何度でも、どの順番でも使えます。最終的に文字列AをBに変形できればYes。

制約

  • T: テストケース数（1 ≤ T ≤ 3×10⁵）
  • A, B: (・x・) だけからなる文字列（長さ1以上）
  • 全テストケースの文字列長の合計：Σ(|A|+|B|) ≤ 2×10⁶
💡 合計200万文字を処理するため、1文字あたりO(1)の処理が必要です。

入出力例

#AB答え理由
1 (xx)x x(xx) Yes (xx)x →操作1→ xxx →操作2→ x(xx)
2 (x)x (xx) No 正規形が (x)x ≠ xx で異なる
3 )x()x( )x()x( Yes 同じ文字列なので操作0回
4 x (x) No xが1つのみで操作2が使えない
失敗アプローチ

「全パターン試す」はなぜダメか？

操作1と操作2が互いに逆の操作のため、BFSを試みると無限ループに陥ります。

⚠️ 無限ループ問題:
操作1: (xx) → xx
操作2: xx → (xx)

この2つは互いに逆。(xx) → xx → (xx) → xx → ... と永遠に往復できてしまいます。
⚠️ 訪問済み管理も現実的でない:
文字列の長さが最大200万文字。取りうる状態数が爆発し、全状態を保持することは不可能です。
💡 発想の転換 — 「何が変わらないか」を探す
「どう変換するか」を追うのではなく、操作で変わらない性質（不変量）を見つけましょう。
AとBの不変量が同じ → Yes、違う → Noという判定が成立します。
キーとなる発見

正規形（これ以上変えられない最小の形）

操作1（(xx)→xx）だけを繰り返すと、やがて(xx)が1つもない形に収束します。これを「正規形」と呼びます。

正規形の例

元の文字列正規形操作の流れ
(xx)xxxx(xx)x →操作1→ xxx（これ以上操作1を使えない）
x(xx)xxxx(xx) →操作1→ xxx
(((xx)))xxx(((xx))) → ((xx)) → (xx) → xx
(x)x(x)x(xx)パターンがないので操作1を使えない → そのまま
🏢 仕事で例えると…
書類に「不要な括弧（装飾）」を付けたり外したりできます。
飾りを全部外した「最もシンプルな形（正規形）」が書類の本質です。
本質が同じなら、どんな飾りも付け直せる = 変換可能！
✅ 判定方法
正規形(A) == 正規形(B) → Yes（変換可能）
正規形(A) != 正規形(B) → No（変換不可能）

正規形はどの順で操作1を適用しても一意に決まります。あとは「正規形を効率よく計算する方法」だけ考えれば解けます。
スタックアルゴリズム

スタックで正規形を1パスO(n)で求める

ナイーブに操作1を繰り返すとO(n²)ですが、スタックを使えばO(n)で計算できます。

スタックのルール（3つだけ）

  • ルール1: ) 以外の文字（( や x）はそのままスタックに積む
  • ルール2: ) を読んだとき、スタック上位3つが (・x・x なら → 3つ取り出して x,x を積む（括弧だけ消す）
  • ルール3: ) を読んだとき、条件を満たさなければ ) をそのまま積む

実行例: (xx)x を処理する

読む文字 操作 スタックの状態
( → そのまま積む [ ( ]
x → そのまま積む [ (, x ]
x → そのまま積む [ (, x, x ]
) → トップ3が (xx) → 3つ取出し x,x を積む [ x, x ]
x → そのまま積む [ x, x, x ]
結果: 正規形 = xxx
canonical 関数の計算量
O(n)
各文字は最大1回pushして1回pop
全体の計算量
O(Σ|A|+|B|)
≤ 2×10⁶ → Pythonでも余裕
内側から自然に処理される理由:
スタックには既に処理済みの文字が積まれているため、ネストした (((xx))) でも一番内側の (xx) から順番に消えていきます。再帰や複数パスは不要です。
完成コード

完成コード — 25行で解ける

canonical関数でスタックを使って正規形を計算し、AとBを比較するだけです。

abc454_d.py ✅ AtCoder にて AC 確認済み 
import sys
input = sys.stdin.readline

def canonical(s):
    stack = []
    for c in s:
        if c != ')':
            stack.append(c)
        elif (len(stack) >= 3 and
              stack[-1] == 'x' and
              stack[-2] == 'x' and
              stack[-3] == '('):
            stack.pop()   # x を取り出す
            stack.pop()   # x を取り出す
            stack.pop()   # ( を取り出す
            stack.append('x')  # x,x はそのまま残す
            stack.append('x')
        else:
            stack.append(')')
    return stack

T = int(input())
for _ in range(T):
    A = input().rstrip()
    B = input().rstrip()
    if canonical(A) == canonical(B):
        print("Yes")
    else:
        print("No")

コードの要点

  • input = sys.stdin.readline — 大量の入力を高速に読み込む
  • stack[-1], stack[-2], stack[-3] — Pythonのリストはマイナス添字で末尾から参照できる
  • 戻り値はリスト — == 演算子でリスト全体を比較するだけなので十分
  • input().rstrip() — sys.stdin.readline は行末の \n を含むため除去が必要

用語解説

このエピソードで登場した用語の読み方と概要

スタック stack

後から入れたものを最初に取り出すデータ構造（LIFO）。Pythonのリストで append/pop を使って実現する。皿を積み上げるイメージ。

Wikipedia: スタック 🔗
正規形 せいきけい / canonical form

変換操作を繰り返してたどり着く「これ以上変えられない標準の形」。同じ正規形を持つ文字列どうしは互いに変換可能。

LIFO ライフォ

Last In, First Out（後入れ先出し）の略。スタックの動作原則で、最後に追加した要素を最初に取り出す。

Wikipedia: スタック 🔗
不変量 ふへんりょう / invariant

操作を何回行っても変わらない性質のこと。「不変量が同じ = 変換可能」という考え方は競プロで頻出。

Wikipedia: 不変量 🔗
list.append() アペンド

Pythonリストの末尾に要素を追加するメソッド。スタックへの「積む（push）」操作に使う。計算量O(1)。

list.pop() ポップ

Pythonリストの末尾から要素を取り出すメソッド。スタックからの「取り出す（pop）」操作に使う。計算量O(1)。
