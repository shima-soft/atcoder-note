失敗アプローチ

「繰り返しチェック」はなぜ遅いか？

ポイント

「変化があるうちは何度でも全交換リストを見直す」は O(N×M) になりTLEになる

ナイーブな実装イメージ
items = {1}         # 最初はアイテム1だけ
changed = True

while changed:      # 変化がなくなるまで繰り返す
    changed = False
    for a, b in trades:
        if a in items and b not in items:
            items.add(b)
            changed = True  # また変化した

print(len(items))
⚠️ 計算量の問題
アイテムは最大 N回 追加される
1回の追加ごとに M件 の全交換を再確認
→ 合計 N × M = 9 × 10¹⁰ 回
→ Python は 1秒に約 10⁷〜10⁸ 回なので
　 1000秒以上かかる → TLE 💀
💼 仕事で例えると
1

社員名簿（M人分）を先頭から全部確認する

2

1人でも「新しく連絡できる人」が見つかったらまた先頭から確認

3

もう誰も増えなくなるまで何度も繰り返す

→ 社員数が30万人いたら何十億回も確認することに…
❌ TLEになる理由まとめ
  • N=M=3×10⁵ のとき N×M = 9×10¹⁰ 操作
  • Python の実行可能上限は約 10⁷（1秒）
  • N ≤ 3000 ならO(N²)でも通るが、今回は10万倍以上大きい
💡 「同じ場所を2度見ない」発想が必要
  • 一度確認したアイテムは二度と繰り返さないアルゴリズムを使う
  • → BFS（幅優先探索）で O(N+M) に改善できる
