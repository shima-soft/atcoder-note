問題を読み解く

アイテム交換で何種類手に入るか？

友達との交換を繰り返して、最終的に「入手可能」なアイテムの種類数を求める問題です。

問題文（噛み砕き版）

N種類のアイテム（番号1〜N）があり、最初はアイテム1だけ持っています。
M人の友達がいて、友達 i にアイテム Ai を渡すとアイテム Bi がもらえます。
交換を組み合わせることで手に入れられるアイテムは何種類か（アイテム1を含む）？

制約

  • N: アイテムの種類数（2 ≤ N ≤ 3×10⁵）
  • M: 友達の数（1 ≤ M ≤ 3×10⁵）
  • Ai, Bi: 交換で使うアイテム番号（Ai ≠ Bi）
💡 N, M ともに最大30万。処理が重すぎるアルゴリズムはTLEになります。

入出力例

例NM交換ペア（一部）答え
1551→2, 2→3, 3→4, 2→4, 5→24
2322→1, 3→21
3781→6, 1→2, 2→3, 2→5, 3→7, ...6
例1の手順: 1を持っている → 1→2交換 → 2を持つ → 2→3交換 → 3→4交換 → {1,2,3,4} = 4種類
例2の手順: 1しか持っていない → 2も3も持っていないので交換不可 → {1} = 1種類
失敗アプローチ

「繰り返しチェック」はなぜ遅いか？

最初に思いつく「変化がなくなるまで全交換を繰り返し確認する」方法は O(N×M) でTLEになります。

ナイーブな実装イメージ

naive_approach.py（TLEになる例） ❌ TLE 
items = {1}         # 最初はアイテム1だけ
changed = True

while changed:      # 変化がなくなるまで繰り返す
    changed = False
    for a, b in trades:
        if a in items and b not in items:
            items.add(b)
            changed = True  # また変化した

print(len(items))
⚠️ なぜTLEになるか:
アイテムは最大 N 回追加される。1回の追加ごとに M 件の全交換を再確認する。
N=M=3×10⁵ のとき N×M = 9×10¹⁰ 回 の処理が必要。
Python は1秒に約 10⁷〜10⁸ 回 → 1000秒以上かかる。制限時間に到底間に合わない。
💡 必要な発想: 「同じノードを2度処理しない」アルゴリズムを使う → BFS で O(N+M) に改善できる。
グラフへの変換

交換の連鎖を「地図」として描く

アイテム交換をグラフ問題に変換すると、「ノード1から到達できるノードを数える」問題になります。

変換ルール

  • 各アイテム番号（1〜N）を ノード（丸） として配置する
  • 交換ペア（A_i, B_i）を A_i → B_i の矢印（有向辺） として追加する
  • ノード1から矢印をたどって到達できる全ノードを数えると答えになる
仕事での例え:
「Aさんが知っている情報はBさんに伝えられる」という社内連絡網。
最初は自分（ノード1）だけが情報を持っている。
矢印をたどって情報が届く全員を数える問題です。

例1の変換結果

交換ペア: (1→2), (2→3), (3→4), (2→4), (5→2)

  • ノード1（スタート）から矢印をたどると: 1→2→3→4 に到達できる
  • ノード5は「5→2」の矢印があるが、ノード5に到達できないので使えない
  • 到達可能: {1, 2, 3, 4} = 4種類

矢印は一方通行です。A→B があっても B→A には戻れません（これを「有向グラフ」と呼びます）。

BFS 解法

BFS で「一度行った場所には戻らない」

キューと visited フラグを使い、各ノードを1回だけ処理することで O(N+M) を実現します。

BFS の手順（例1で追う）

  • STEP 0: ノード1をキューに入れ、visited[1]=True にする。キュー=[1]
  • STEP 1: キューからノード1を取り出す。隣（矢印先）はノード2。未訪問なのでキューに追加。キュー=[2], visited={1,2}
  • STEP 2: キューからノード2を取り出す。隣はノード3と4。どちらも未訪問なので追加。キュー=[3,4], visited={1,2,3,4}
  • STEP 3〜4: ノード3・4を処理するが新発見なし。キューが空になる。
  • 結果: visited = {1, 2, 3, 4} → 4種類
BFS の計算量
O(N+M)
各ノード・各エッジを1回ずつ処理
N=M=3×10⁵ のとき
≈ 6×10⁵ 回
Python でも余裕で1秒以内
O(N+M) になる理由:
各ノードはキューに 1回だけ 追加される。各エッジも 1回だけ チェックされる。
visited フラグのおかげで、グラフに循環があっても無限ループしない。
完成コード

BFS 実装 — 18行で完成

collections.deque をキューに使い、visited リストで二度訪問を防ぎます。

abc454_c.py ✅ AtCoder にて AC 確認済み 
from collections import deque

N, M = map(int, input().split())

# 隣接リスト: graph[a] に a→b の b を追加
graph = [[] for _ in range(N + 1)]
for _ in range(M):
    a, b = map(int, input().split())
    graph[a].append(b)

# BFS
visited = [False] * (N + 1)
visited[1] = True
queue = deque([1])

while queue:
    node = queue.popleft()
    for next_node in graph[node]:
        if not visited[next_node]:
            visited[next_node] = True
            queue.append(next_node)

print(sum(visited))

コードの要点

  • graph[a].append(b) — 交換をグラフのエッジとして記録
  • deque([1]) — ノード1をキューに入れてスタート
  • visited[next_node] = True — 二度訪問しないようにフラグを立てる
  • sum(visited) — True の数（到達したノード数）を出力
  • deque を使う理由: list の pop(0) は O(N) だが deque の popleft() は O(1)
グラフ構築
O(M)
M本のエッジを1回追加
BFS探索
O(N+M)

用語解説

このエピソードで登場した用語の読み方と概要

BFS（幅優先探索） ビーエフエス

グラフを「近い順」に広がりながら探索するアルゴリズム。キューを使い、スタートから届く全ノードを効率よく発見できる。

Wikipedia 🔗
有向グラフ ゆうこうグラフ

矢印（向き付き辺）で接続されたノードの集まり。A→B の矢印があっても B→A には戻れない。今回の「交換ペア」が有向辺に相当する。

deque（両端キュー） デック

Python の collections モジュールにある両端キュー。先頭への取り出しが O(1) で行えるため BFS に最適。list.pop(0) の代わりに使う。

docs.python.org 🔗
隣接リスト りんせつリスト

グラフの辺情報を「各ノードの隣人リスト」として持つ表現方法。N×N の隣接行列より省メモリで、スパースなグラフに向く。

O(N+M) 記法 オーダー・エヌプラスエム

計算量の表記。N がノード数、M がエッジ数のとき BFS は O(N+M)。N=M=3×10⁵ なら約 6×10⁵ 回 → Python でも十分速い。
