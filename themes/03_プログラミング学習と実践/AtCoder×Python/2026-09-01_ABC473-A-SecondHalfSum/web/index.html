Second Half Sum

長さ N（偶数）の数列をちょうど半分に分け、後ろ半分だけを足す問題。やることは足し算だけですが、「問題文の◯番目」と「Python の添字」のズレでつまずきやすい1問です。

1

半分に分ける

N は必ず偶数。後半の個数はいつも N ÷ 2 個

2

開始位置を決める

後半の先頭は Python の添字で n // 2

3

順に足す

そこから最後まで for ループで足すだけ

問題を読み解く

長さ N の整数の並び（数列）A が与えられます。N は必ず偶数です。この数列をちょうど半分に分けたときの後ろ半分の合計、つまり N ÷ 2 + 1 番目から N 番目までを足した値を出力してください。

制約が示すこと

2 ≤ N ≤ 100（N は偶数）、1 ≤ A の各要素 ≤ 100。N が偶数と保証されているので「半分に割り切れない」場合を考えなくてよい。数も小さいので、工夫せず素直に足すだけで十分。

入力の形式（2行）

N A1 A2 … AN

1行目に個数 N、2行目に N 個の数が空白区切りで並ぶ。読み込みは2回に分かれる点に注意。

入出力例で確認する

入力出力なぜそうなる？
8
1 3 7 8 4 2 5 6		17後ろ半分は 4・2・5・6 の4個。4+2+5+6 = 17
2
1 100		100後ろ半分は 100 の1個だけ。そのまま 100
10
31 41 59 26 53 58 97 93 23 84		355後ろ半分は 58・97・93・23・84 の5個。合計 355
セルフチェック：入力例1で前半を足してしまうと、いくつになる？

1+3+7+8 = 19。全部足すと 36。どちらも正解の 17 とは違う値になるので、「どこからどこまで足すか」を最初にはっきり決めておくことが大切。

入力例1を、紙とペンで解いてみる

コードを書く前に、入力例1を手で解いてみます。1 3 7 8 4 2 5 6 の8個を4個ずつに区切り、右側の4個だけを左から順に足していくだけです。前半の 1・3・7・8 には一度も触りません。

答え合わせ

4 + 2 + 5 + 6 = 17。出力例1と一致します。足した回数は4回で、8個あっても半分しか触っていないのが分かります。

やってしまいがち

前半を足すと 1+3+7+8 = 19、全部足すと 36。どちらも 17 になりません。どこからどこまで足すかを最初に決めてから書き始めます。

ここまでで十分

この「半分に区切って後ろだけ足す」という手作業が、そのままプログラムになります。難しいアルゴリズムは要りません。あとは、この手順をどんな N でも通じる形に直すだけです。

セルフチェック：入力例2（N=2、1 100）を手で解くと？

後半は 2 ÷ 2 = 1個だけ。つまり2番目の 100 がそのまま答え。前半の 1 は使いません。

どんな N でも、境目は N ÷ 2 のところ

手でやった区切り方は、N がいくつでもそのまま通じます。下の図は入力例1（N = 8）と入力例3（N = 10）を並べたものです。どちらも境目はちょうど真ん中で、後半の個数は N ÷ 2 個。N が偶数と決まっているので、割り切れないケースを気にする必要はありません。

後半の見つけ方

後半の個数は N ÷ 2 個。問題文の数え方だと N ÷ 2 + 1 番目から始まる。N=8 なら 5番目から8番目までの4個。

うっかりしやすい点

前半を足すと 19、全部足すと 36 になってしまう。「後ろ半分」という言葉に引きずられて、どこが境目かを曖昧にしたまま書き始めないこと。

💡 仕事に例えると

12か月分の売上リストから下半期（7月〜12月）だけを集計するのと同じ作業です。前半6か月と後半6か月に区切り、後半だけを取り出して足す。表計算ソフトで範囲を選んで合計を出すときの、あの「範囲の指定」がそのままプログラムになります。

セルフチェック：N = 10 のとき、後半は何番目から何番目？

10 ÷ 2 = 5 なので、後半は 6番目から10番目までの5個。入力例3ではこれが 58・97・93・23・84 にあたる。

番号と添字の1つのズレ

この問題でいちばん間違えやすいのがここです。問題文は「1番目・2番目…」と 1 から数えますが、Python のリストは 0 から数えます。同じマスを指していても、呼び名が1つずれるのです。

覚え方はこれだけ

問題文の「◯番目」は、Python では ◯ − 1 番の添字。だから後半の先頭「N ÷ 2 + 1 番目」は、添字にすると n // 2。+1 が消えるのがポイント。

1つずれる典型ミス

問題文の +1 をそのまま書いて a[n // 2 + 1:] にすると、6番目から足すことになり1個足りない。入力例1では 17 ではなく 13 が出る。

手を動かして確かめる

N=8 のとき n // 2 は 4。a[4] は5番目の値である 4 を指します。「4番目じゃないの？」と迷ったら、a[0] が1番目だと思い出せば、添字4は5番目だとすぐ確かめられます。

セルフチェック：a[n // 2 + 1:] だと入力例1でいくつになる？

a[5:] つまり 2・5・6 の3個だけ足すことになり、13。1個少ないだけで答えが変わってしまう。

AC想定コード

公式サンプル3件で出力が一致することを確認済みです。後半の開始位置を n // 2 で求め、そこから最後まで順に足していくだけの9行です。

abc473a.py ✅ 公式サンプル確認済み 
n = int(input())
a = list(map(int, input().split()))

half = n // 2
total = 0
for i in range(half, n):
    total = total + a[i]

print(total)

1〜2行目 — 入力を受け取る

1行目の個数を int(input()) で整数にして n へ。2行目は input().split() で空白ごとに切り分け、map(int, ...) で全部を整数に変え、list(...) でリスト a にまとめる。

4〜5行目 — 開始位置と合計の箱

n // 2 は割り算の答えを整数で求める書き方。n=8 なら half は 4 になり、これが後半の先頭の添字。合計を入れる total は 0 から始める。

6〜7行目 — 後半だけを足す

range(half, n) は half から n の1つ手前までの番号を順に出す。n=8 なら 4・5・6・7 の4回まわり、a[i] を total に足していく。

9行目 — 出力

足し終えた total をそのまま表示する。出力は答えの数値1つだけなので、余計な文字を付けないよう注意。

慣れてきたら：スライスで1行に

a[half:] は「half 番の添字から最後まで」を切り出す書き方。合計を出す sum() と組み合わせると print(sum(a[half:])) の1行で書けます。まずはループで書いて動きを追い、納得してから短くするのがおすすめです。

セルフチェック：range(half, n) の n は足す対象に含まれる？

含まれません。range(4, 8) は 4・5・6・7 の4つで、8 は出てきません。この「終わりの値は含まない」決まりのおかげで、最後の添字 n−1 までちょうど足せます。

初めて見る数列で、自分で解いてみる

ここまでの手順を、まだ扱っていない数列に当ててみます。読んで分かった気になるのと、自分で一度解いてみるのとでは、次の問題での手応えがまったく違います。答えを見る前に、まず自分で計算してみてください。

詰まったときのヒント

N = 6 なので、前半3個・後半3個に分かれます。Python なら half = 6 // 2、つまり添字 3 から最後まで。

引っかかりやすいところ

「4番目から」と数えて 7・1・5 を足せば正解。5番目からにすると1個足りません。問題文の「N ÷ 2 + 1 番目」の +1 に引きずられないこと。

答えを見る（先に自分で解いてから開いてください）

後ろ半分は 7・1・5 の3個。7 + 1 + 5 = 13 が答えです。Python なら print(sum(a[3:])) でも同じ結果になります。

まとめ

1

N が偶数と書いてあれば「ちょうど半分に割れる」と読み取れる

2

問題文の「◯番目」は、Python の添字では ◯ − 1 になる

3

開始位置さえ決まれば、あとは for ループで足すだけ

A問題は「難しいことをしない」のが正解です。むしろ差がつくのは、問題文の数え方をプログラムの数え方に正しく翻訳できるかという一点。ここを毎回ていねいに確かめる習慣は、この先のB・C問題でもそのまま効いてきます。
