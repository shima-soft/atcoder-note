Coefficient Stair

重み付き和 Σ i×A_i = K をちょうど満たす非負整数列を、辞書順で小さい方からすべて出力する。到達可能性DPで無駄な枝を先に切り、DFSで辞書順のまま列挙します。

1

小さい順に試す

各位置でvを0から試すだけで辞書順のまま解ける

2

行き止まりを先読み

「残りが作れるか」を先にDPの表にしておく

3

枝刈りDFS

作れない枝はその場で切り捨て、出力数に見合う速さで列挙

問題を読み解く

非負整数からなる長さNの数列 A=(A_1, ..., A_N) を考える。位置iに「重みi」を掛けて全部足すと、ちょうどKになるものを辞書順で小さいほうからすべて出力する。

制約が示すこと

1≤N≤10、1≤K≤2×10⁵。条件を満たす数列は3×10⁵個以下であることが保証されている。Nが最大10というかなりの小ささが「全探索してよい」という出題者からのメッセージ。

入力例1（N=3, K=8）

3 8

(0,1,2) は 0×1+1×2+2×3=0+2+6=8 で条件を満たす。これより辞書順で小さい数列はないので1行目。全部で10個の数列が条件を満たす。

セルフチェック：入力例2（N=1, K=200000）の答えは？

200000 の1行だけ。N=1のときは A_1=K しかありえないので、答えは常に1個だけになる。

数列 (0, 1, 2) を、手で計算して確かめる

この問題の条件は、言葉だけだと分かりにくいので、まず実際の数字で1回解いてみます。N = 3、K = 8 のとき、数列 (0, 1, 2) が条件を満たすかどうかを手で確かめます。やることは「1番目の値に 1 を掛け、2番目の値に 2 を掛け、3番目の値に 3 を掛けて、全部足す」だけです。この掛ける数のことを、この記事では重みと呼びます（問題名の Coefficient がこれにあたります）。

分かったこと

1×0 + 2×1 + 3×2 = 0 + 2 + 6 = 8。K と一致するので (0, 1, 2) は条件を満たします。これが出力例1の1行目です。探すのは「重み × 値」の合計がちょうど K になる並び、それだけです。

ここが大変

条件を満たす数列は1つではありません。全部を辞書順で出す必要があります。N = 3, K = 8 という小さな例でも答えは10行あり、手で全部探すのは現実的ではありません。

セルフチェック：(1, 1, 1) は条件を満たす？

1×1 + 2×1 + 3×1 = 1 + 2 + 3 = 6。K = 8 と一致しないので、条件を満たしません。

総当たりでは、候補のほとんどが最後に外れる

N ≤ 10 だからと何も考えずに全探索すると、行き止まりの枝を大量に踏むことになります。位置1から順に 0〜K を総当たりし、最後の位置で割り切れるかだけを確認する方式では、組み合わせ数が最大 (2×10⁵)⁹ 通りにも達します。一方で条件を満たす数列は最大 3×10⁵ 個。候補のほとんどは答えになりません。

何が無駄なのか

条件を満たす数列は最大でも 3×10⁵ 個だけなのに、「作れない」候補まで律儀に最後の位置まで進めてしまう。外れだと分かるのが遅すぎる。

制約が教えてくれること

N ≤ 10 は「全探索してよい」の合図。ただし枝の刈り方が要る。K ≤ 2×10⁵ なので、残りの値ごとに表を持てる大きさに収まる。

セルフチェック：何が一番無駄なのか？

「作れない」と最後まで進んで初めて分かる点。手前で分かれば、その先を一切探索せずに済む。

「残りをこの先の重みで作れるか」が先に分かればいい

総当たりの無駄は、行き止まりだと分かるのが最後だという点にありました。では、途中で分かるようにするには何が要るでしょうか。位置を1つ決めた時点で「残りをこの先の重みだけで作れるか」が分かれば、作れない枝はその場で打ち切れます。

何がうれしいか

1番目に 7 を置くと残りは 1。この先で使えるのは重み 2 と 3 だけなので、1 は作れません。2番目・3番目を調べる前にこの枝を丸ごと捨てられます。最後まで進んでから外れるのではなく、その場で切れるのが違いです。

まだ足りないこと

「作れるか」を毎回その場で計算し直すと、結局そこが遅くなります。先に表にしておく必要があります。それが次の節の reach です。

💼 仕事で例えると

今月あと使える経費枠がちょうど1万円残っているとします。これから申請できるのが2万円と3万円の品だけなら、枠はどうやっても使い切れません。それが先に分かっていれば、以降の申請を検討する手間がまるごと省けます。

セルフチェック：1番目に 6 を置いたら、その枝は進める？

残りは 8 − 6 = 2。重み 2 を1回使えばちょうど 2 になるので進めます（2番目に 1、3番目に 0）。

reach の表を先に作っておく

「作れるか」を毎回その場で計算し直すと遅くなるので、先に表にしておきます。reach[idx][rem] は「重み idx 以降だけで、残り rem をちょうど作れるか」を ○ と − で持つ表です。reach[idx] は1つ大きい reach[idx+1] をコピーしてから、rem を idx, idx+1, … と増やしながら ○ を伝播させて作ります。

仕事で例えると

今月あと自由に使える経費枠がrem円残っているとき、「今後使える単価（idx円, idx+1円, …）だけでrem円ちょうど使い切れるか」を先に一覧化しておくイメージ。

DFSでの使い方

位置idxでA_idx=vを仮決めしたら、残り r=rem−idx×v が reach[idx+1][r] なら先に進む。○の候補だけを辿るので、行き止まりの探索が消える。

セルフチェック：なぜ reach[1] は全部○になる？

重み1があれば、A_1=rem に決めるだけでどんな値も作れてしまうから。coefficientに1が含まれる問題は必ずこうなる。

前ページの手順を、入力例1（N=3, K=8）に当てて動かす

小さい値から順に試し、reach表で作れない枝を即スキップすると出力例1の1・2行目が求まる。

1

idx=1, rem=8 で v=0 を選ぶ（一番小さい値から試す）

2

idx=2, rem=8 で v=0,2,3 は reach[3]が✕なのでスキップ、v=1,4だけ先に進む

3

idx=3（最後）で rem÷3 が確定値になり、そのまま1行出力

セルフチェック：v=7 が試されないのはなぜ？

reach[2][1] = − （重み2,3だけでは1を作れない）とチェックだけで分かるので、実際に深く探索する必要がない。

AC想定コード

公式サンプル3件で出力が一致することを確認済みです。スライドのコード①・②をつなげたものが丸ごと1ファイルになります。1行ずつprint()すると出力3×10⁵行では遅くなるため、文字列をリストに貯めて最後に1回で出力する形にしています。

abc473d.py ✅ 公式サンプル確認済み 
import sys
input = sys.stdin.readline

N, K = map(int, input().split())

reach = [[False] * (K + 1) for _ in range(N + 2)]
reach[N + 1][0] = True
for idx in range(N, 0, -1):
    reach[idx] = reach[idx + 1][:]
    for r in range(idx, K + 1):
        if reach[idx][r - idx]:
            reach[idx][r] = True

A = [0] * N
out = []

def dfs(idx, rem):
    if idx == N:
        A[idx - 1] = rem // idx
        out.append(' '.join(map(str, A)))
        return
    for v in range(rem // idx + 1):
        r = rem - idx * v
        if reach[idx + 1][r]:
            A[idx - 1] = v
            dfs(idx + 1, r)

dfs(1, K)
print('\n'.join(out))
セルフチェック：なぜ1行ずつ print しないの？

出力は最大3×10⁵行。print()を毎回呼ぶと処理コストが積み重なり遅くなります。文字列をリストoutに貯めて'\n'.join(out)で1回にまとめて出力すると大幅に速くなります（N=10, K=64相当の296,320行の出力で計測したところ、1行ずつprintだと約13秒、まとめて出力だと0.6秒でした）。

計算量

項目規模
reach表の構築O(N×K)
DFSによる列挙・出力出力数に応じて変動（最大3×10⁵行）
全体の目安O(N×K) ≈ 最大200万回のループ

N≤10, K≤2×10⁵ なので O(N×K) は最大でも約2×10⁶回。これはO(N)型がPythonで間に合う目安（N≤10⁷）にも収まる規模で、余裕を持って間に合います。

小さい入力で、自分で全部書き出してみる

ここまでの手順を、小さい入力に当ててみます。N = 2 なら手で足ります。答えを見る前に、まず自分で書き出してみてください。手で全部並べてみると、DFS が小さい値から試すだけで辞書順になる理由が腑に落ちます。

詰まったときのヒント

2番目の値 A₂ を 0 から順に試します。A₂ = 0 なら A₁ = 5、A₂ = 1 なら A₁ = 3 …と埋まっていきます。残りがマイナスになったら打ち切り。

引っかかりやすいところ

並べる順は辞書順で、1番目の値が小さいものから先に出します。0 も使ってよい値なので、忘れると1行足りなくなります。

答えを見る（先に自分で解いてから開いてください）

答えは3行です。1 2（1×1+2×2 = 5）、3 1（1×3+2×1 = 5）、5 0（1×5+2×0 = 5）。辞書順なので 1番目の値が小さい順に並びます。

まとめ

1

N≤10 は「全探索してよい」の合図。制約の桁数にまず注目する

2

「残りが作れるか」を reach[idx][rem] として先にDPで判定しておく

3

各位置で候補を0から順に試すDFSは、特別な工夫なしに辞書順になる

「小さい制約に気づく→到達可能性を先にDP→DFSで辞書順に枝刈り列挙」は、全列挙系の問題で繰り返し使えるパターンです。
