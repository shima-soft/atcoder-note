Roads and Gates

全都市ペアのワープを、入口・出口の2つの超頂点へ圧縮。通常の最短経路問題として解きます。

1

N²辺を疑う

完全グラフは作れない

2

式を3辺へ分解

Xᵢ + Y + Xⱼ

3

最短経路

ダイクストラ法を1回

考え方フローチャートを開く →

問題を読み解く

N都市とM本の双方向道路があります。道路iはTi分。都市iから都市jへは、ワープで Xi + Xj + Y 分かかります。都市1から都市2〜Nへの最短時間を求めます。

制約が示すこと

N,M ≤ 2×105。全都市ペアの辺は作れません。値は最大109で、答えは231を超える場合があります。

サンプル1の都市7

都市1→2を道路で1分、都市2→7をワープで1+2+3=6分。合計7分です。

セルフチェック：ワープ料金の3つの部品は？

出発側Xi、全員共通Y、到着側Xjです。

全都市ペアのワープ辺を作る？

約400億本

N=20万で有向辺を全ペアに作ると、N(N−1)本。メモリにも時間にも収まりません。

全支店間の直通便を作るのではなく、共通の物流センターへ集約する発想へ切り替えます。

Xᵢ + Xⱼ + Y を3区間へ

都市 i ─ Xᵢ → 入口 Wₛ ─ Y → 出口 Wₜ ─ Xⱼ → 都市 j

追加する辺

  • 都市i → Wₛ：Xi
  • Wₛ → Wₜ：Y
  • Wₜ → 都市j：Xj

辺数

N²本から 2N+1本へ。どのi,jでも合計料金は元の式と一致します。

セルフチェック：なぜ超頂点が2つ必要？

共通費用Yをちょうど1回通し、入口→出口という向きを表現するためです。

有向辺の向きを守る

都市→ Xᵢ →入口 Wₛ→ Y →出口 Wₜ→ Xⱼ →都市

ワープ

すべて一方向。不要な逆向き辺は追加しません。

道路

双方向なので、u→vとv→uの2本を追加します。

ダイクストラ法を1回

圧縮後はN+2頂点の重み付きグラフです。すべてのコストが正なので、都市1を始点にダイクストラ法を使えます。

1

都市1を0、ほかを∞にする

2

heapから最小候補を取り出す

3

より短い距離なら更新する

提出コード

公式サンプル3件とランダムな小ケースで確認したコードです。

abc463e.py✅ AC想定・公式サンプル確認済み
import sys
import heapq

input = sys.stdin.readline
N, M, Y = map(int, input().split())

graph = []
for _ in range(N + 2):
    graph.append([])

for _ in range(M):
    u, v, T = map(int, input().split())
    u -= 1
    v -= 1
    graph[u].append((v, T))
    graph[v].append((u, T))

X = list(map(int, input().split()))
gate_in = N
gate_out = N + 1

for city in range(N):
    graph[city].append((gate_in, X[city]))
    graph[gate_out].append((city, X[city]))

graph[gate_in].append((gate_out, Y))

INF = 10**30
dist = [INF] * (N + 2)
dist[0] = 0
queue = [(0, 0)]

while queue:
    current_dist, city = heapq.heappop(queue)
    if current_dist != dist[city]:
        continue

    for next_city, cost in graph[city]:
        new_dist = current_dist + cost
        if new_dist < dist[next_city]:
            dist[next_city] = new_dist
            heapq.heappush(queue, (new_dist, next_city))

print(*dist[1:N])

計算量

項目規模
頂点数N + 2
有向辺数2M + 2N + 1
全体O((N + M) log N)

N,M ≤ 2×105。Pythonでも現実的な範囲です。

まとめ

1

2

全ペアに同じ形のコストが現れたら、共通のハブへ圧縮できないか考えましょう。

用語解説

完全グラフすべての頂点ペアが辺で結ばれたグラフ。
超頂点共通経路をまとめるため追加する仮想頂点。
有向辺進める向きが決まった辺。
隣接リスト各頂点から出る辺だけを保存する形式。
ダイクストラ法負辺がないグラフの単一始点最短経路法。
優先度付きキュー最小候補を高速に取り出すデータ構造。
