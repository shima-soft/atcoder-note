INTRO

Opus 4.7 とは？

一言で

コーディング・AIエージェントタスクに最も強い最新の公開モデル。ただし使い方の「慣らし」が必要

Claude Opus 4.7は新しいトークナイザーと進化した推論パターンを持つ。そのため Opus 4.6のプロンプトをそのまま使うと最適でない場合がある。 3点を把握しておくだけで、移行後のギャップに戸惑わなくなる。

① 新しいトークナイザーで処理方式が変わった

テキストの分割方法が更新され、より効率的に処理できるようになった反面、同じプロンプトへの応答が若干変化することがある

② 推論パターンが進化した

より柔軟に「考える」ようになった。問題の難しさに応じて自動で思考の深さを変える「アダプティブ思考」を採用

③ デフォルト動作が変わった

レスポンスの冗長性が低下し、ツール使用も慎重になった。「エフォート設定」という新機能で動作を細かく制御できる

移行の基本スタンス

4.6向けのプロンプトをそのまま使わず、新しい「癖」に合わせて3点チューニングするだけでOK

📝 理解度セルフチェック
新しいトークナイザーの採用と推論パターンの進化により、同じプロンプトへの応答が変化するため。3点のチューニング（thinking_budget削除・effort追加・プロンプト簡素化）が必要。
①新しいトークナイザーで処理方式が変わった ②アダプティブ思考で推論パターンが進化した ③デフォルトの冗長性低下・ツール使用の慎重化
⏱ 3:00〜5:00
POINT 01

Claudeを「有能なエンジニア」として扱う

一言で

「一緒に手を動かすアシスタント」ではなく「仕事を丸ごと任せられる優秀な部下」として接する

💼 実務シナリオ: 月次レポート作成
旧

「次は何のグラフを作ればいい？」と都度Claudeに確認

新

「6月売上CSVを使い、前月比グラフ付きA4 2ページで。競合比較は除く」と最初に全部伝える

✅ 最初に伝えるべきこと
  • タスクの全体像と最終ゴール
  • 成功の基準（どうなれば完成か）
  • やらなくていいこと（除外事項）
⚠️ 失敗パターン
  • 「いい感じに」「適当に」などの曖昧表現
  • 途中で仕様を小出しに変更する
📝 理解度セルフチェック
エンジニア型は最初に包括的な仕様を渡してあとは任せる。ペア作業型は都度確認しながら進める。エンジニア型の方がコスト・時間・品質すべてで優れる。
⏱ 5:00〜7:00
POINT 02

タスクを包括的に指定する技術

一言で

あいまいな指示は途中停止の原因。最初に「何を・どのレベルまで・何をやらないか」を伝える

💼 提案書作成 NG vs OK
❌

「A社向けの提案書を作って」（ゴール・形式・除外不明）

✅

「A社向けにクラウド移行の提案書をPPT形式6枚で。価格比較はCFO確認済みのものを使い、競合言及は除く」

✅ 指示テンプレート
  • 「〇〇を使って△△し、□□形式で出力」
  • 「〜〜は不要、〜〜は除く」を必ず追加
📝 理解度セルフチェック
①何を（タスクの全体像と最終ゴール）②どのレベルまで（成功の基準・品質・形式）③何をしない（除外事項・スコープ外）の3点を最初に伝える。
⏱ 7:00〜9:30
POINT 03

エフォート設定 — 5段階の賢い使い分け

一言で

問題の難しさに合わせてAIの「考える深さ」を調整。コストと精度のバランスが鍵

設定値 使いどき（業務例） コスト 速度
low メール文面チェック・簡単なデータ変換・定型コピー ★☆☆☆☆ 最小 ⚡ 最速
medium 標準的な文書要約・ルーティンコーディング・FAQ回答 ★★☆☆☆ 低め 🚀 速い
high 要件整理・中規模なコード修正・競合調査レポート ★★★☆☆ 中程度 🏃 普通
xhigh推奨デフォルト ほとんどの開発作業・複雑な資料作成・システム設計 ★★★★☆ やや高め 🚶 やや遅
max 本番バグ修正・難解な仕様策定・高度な分析・意思決定 ★★★★★ 最大 🐢 遅い
💡 ほとんどの作業は「xhigh」がベストバランス。「max」は難題に限定——すべてに使うとコストが跳ね上がる。 簡単なチェック作業は「low / medium」でコストを抑えよう。
📝 理解度セルフチェック
xhigh。コストと品質のベストバランスを提供するため。ほとんどの開発作業や資料作成で十分な品質が得られる。maxはすべてに使うと収穫逓減があり過剰になる。
デフォルト動作（xhigh相当）になるが、明示的に設定することで意図を明確にし、コストを最適化できる。特に low/medium に下げると大幅なコスト削減が可能。
⏱ 9:30〜11:30

POINT 05

Opus 4.7 の4つの行動変化

一言で

4.6との違いを知っておけば「なんか変だな？」を感じたときにすぐ原因がわかる

1 レスポンス長
🎯 タスクの難しさに応じて長さが変わる
シンプルな質問には簡潔に、複雑な問題には詳しく返答する。詳細が欲しいときは「詳しく説明して」と指示すればOK。
2 冗長性
📝 デフォルトの冗長性が低下した
前置き・締めくくりが減少。「まず〜を説明します」などが少なくなった。「ステップごとに詳しく説明して」と明示すれば長く書いてくれる。
3 ツール使用
🔧 ツール使用が慎重になった
ツールをすぐ使わず、まず推論で解決しようとする。精度が上がる。明示的にツール使用を指示すればすぐ動く。
4 サブエージェント
🤖 サブエージェント生成が節制的に
本当に必要な場合のみ生成するようになった。コストの無駄遣いが自然に減る。大規模タスクでの不必要なコスト増大が抑えられる。
📝 理解度セルフチェック
「詳しく説明して」「ステップごとに説明して」と明示的に指示する。4.7は「必要十分」が基本なので、詳細が必要なときは要求すれば対応してくれる。
⏱ 13:30〜15:00
MIGRATION

4.6 → 4.7 移行チェックリスト

一言で

Opus 4.6をそのまま4.7に換えるだけでは性能が出ないことがある。3点を確認しよう

1
thinking_budget の設定を削除する
thinking_budget=5000 ← 削除 // アダプティブ思考に任せる（設定不要）
固定予算は Opus 4.7 では非対応。削除するだけでOK — アダプティブ思考が自動で最適化してくれる
2
エフォート設定「xhigh」をデフォルトに追加
// effort設定なし ← 追加が必要 effort: "xhigh" ← 追加
ほとんどの作業は xhigh がベスト。コスト重視なら high、難題は max に変更できる
3
プロンプトの見直し（冗長な指示を整理）
「詳しく・丁寧に・ステップを分けて…」← 過剰指示は削除 「〇〇をして。必要なら詳しく説明を加えて」← シンプルに
4.7はより賢くなっているので、余分な指示は逆効果になることがある。シンプルに目的だけ伝えよう
⚠️ よくある移行の失敗
  • 4.6向けのプロンプトをそのまま使って「なんか違う」
  • thinking_budgetを削除し忘れてエラーが出る
  • 冗長な指示が多すぎてClaudeが混乱する
✅ 移行成功のサイン
  • シンプルな指示で期待通りの結果が出る
  • 難しい問題で自動的に深く考えてくれる
  • コスト効率が4.6より改善している
📝 理解度セルフチェック
①thinking_budgetの削除 ②effort:"xhigh"の追加 ③プロンプトの簡素化（過剰な指示を整理）
⏱ 15:00〜16:30
POINT 06

Auto モードで自律作業を最大化する

一言で

人が都度確認しなくてもClaudeが最後まで走り切る設定と、完了通知で仕事を任せきれる

WRAP UP

まとめ — 今日から試せる3つのアクション

一言で

3点の設定変更で、Claude Opus 4.7 の真の実力を引き出せる

1
エフォート設定を「xhigh」に変える
ほとんどの作業でコストと品質のベストバランス。最初の設定として迷ったらこれ一択。難しい問題は max に、簡単な確認は low/medium に使い分けよう。
effort: "xhigh"
2
thinking_budget の指定を削除する
Opus 4.7 はアダプティブ思考で問題の難しさを自動判定する。固定予算の手動設定は不要になった — 削除するだけで自動最適化してくれる。
thinking_budget の行を削除
3
タスクを「走り切れる仕様書」として最初に伝える
「何を・どのレベルまで・何をしないか」を最初に全部書く。途中の都度確認をなくすことで、コストも品質も改善する。

GLOSSARY

用語解説

このスライドで登場した用語の読み方と概要

Claude Code クロード・コード claude.ai/code 🔗

Anthropicが提供するAIコーディングアシスタント。ターミナルやIDEから直接Claudeを呼び出せる。プログラミング知識がなくても文章で指示するだけで動く。

Claude Opus 4.7 クロード・オーパス・フォー・セブン anthropic.com 🔗

Claudeシリーズの最上位モデル（2026年4月公開）。コーディングとエージェントタスクに特に強く、アダプティブ思考とエフォート設定を新搭載。

エフォート設定 エフォートせってい

AIが問題解決にかける「考える深さ」を5段階（low / medium / high / xhigh / max）で調整する機能。Opus 4.7の新機能。ほとんどの作業は xhigh がベスト。

アダプティブ思考 アダプティブしこう

問題の難しさをAIが自動判定し、必要な思考量を動的に配分する機能。Opus 4.7から採用。以前の固定予算（thinking_budget）指定が不要になった。

サブエージェント サブエージェント

複雑なタスクを処理するためにメインのAIが必要に応じて呼び出す補助的なAIエージェント。Opus 4.7では必要な場合のみ節制的に生成され、コスト最適化される。

Anthropic アンソロピック anthropic.com 🔗

Claudeを開発した米国のAI企業（2021年設立）。安全なAIの研究・開発を目指し、Claude Code・Claude APIなど多数のツールを提供している。

トークナイザー トークナイザー

テキストを小さな単位（トークン）に分割するAIの処理機構。Opus 4.7では更新されより効率的に処理できるようになった。料理に例えると「食材を切り分ける包丁」のような存在。

Auto モード オート・モード

人の介入なしにClaudeが最後まで自律的にタスクを実行するモード。「朝タスクをセット→通知を受けて夕方にレビュー」という使い方が可能。

推論（Thinking） すいろん・シンキング

AIが問題を解くために内部でステップを踏んで考えるプロセス。人間が紙に計算を書き出して考えるように、AIも内部で思考ステップを踏む。深い推論ほど精度が上がる。

エージェント エージェント

目標を達成するために自律的に判断・行動するAIプログラムの総称。会社で言えば「指示なしに仕事を進められる優秀な部下」のようなもの。
